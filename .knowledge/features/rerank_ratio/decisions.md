# rerank_ratio — Decisions

## Chosen approach + why

Replace the post-rerank selection rule with **top-1 kept unconditionally + rank≥2 kept iff `score >= top_score * RATIO`**, with **RATIO = 0.6**, and **drop the absolute floor entirely** (calibrated from the A/B run of 2026-08-06 against baseline fd5fc67; shipped in commit 9f48018, branch feature/fastapi, 2026-08-07).

- RATIO 0.6 chosen from an offline sweep over the A/B calibration output (`evals/v2/results/ab_phrasing_20260806_163755.json`, 26 paired questions, 1040 candidates). At 0.6: formal keeps gold 26/26, abbreviated keeps gold 24/26 (the practical ceiling — the other 2 are unreachable by any ratio, see below), noise ~0.35 docs/query on abbreviated, 20/26 queries fully noise-free. 0.6 is the knee: raising it starts dropping gold (id=13 gold-ratio-to-top is 0.837, id=15 is 0.879 — a ratio above those kills them), lowering it admits more noise without recovering any additional gold (0.5 and 0.6 both give 24/26).
- Absolute floor dropped in **both** roles it was serving. As a top-1 gate it was falsifiable: id=4's gold top-1 scored 0.00071 yet is correct, so any floor > 0.001 refuses a valid query. As a rank≥2 sanity floor it was proven redundant by a second sweep (ratio fixed at 0.6, floor swept 0.0→0.2): floor 0.01 already drops abbreviated gold from 24→23 while removing only ~0.08 noise/query, and 0.01→0.20 changes nothing further (every noise doc surviving ratio 0.6 already scores >0.2). The ratio does all the filtering; the floor only adds harm.

## Assumptions it rests on

- **Reranker scores are not comparable across queries**, so gating must be relative (ratio to this query's top-1), never absolute. If a future reranker produced calibrated/comparable scores, an absolute floor could return.
- **The answer LLM can disambiguate near-tied documents better than the cross-encoder can.** RATIO 0.6 deliberately keeps *all* documents within 60% of top-1, including same-topic-wrong-level articles (Đ15 vs Đ24). This is correct only if the generator, given full parent context, picks the right one. If the generator is weak or context-window-limited, this floods it with wrong-level material.
- **Retrieval recall is adequate**: ratio only re-ranks/keeps what is already in the candidate pool. It cannot recover gold that retrieval never fetched. The 26-question A/B set is small; the tail (worst-case gold score) is one sample, so 0.6 is a defensible knee, not a proven optimum. Re-sweep if the corpus grows or retrieval changes.
- Calibration validity: the A/B numbers were generated on the **current hybrid+PDR retrieval** with query rewrite enabled, so they reflect the live pipeline's score distribution. Only the *thresholding* step changed since; raw scores did not, so the sweep is still valid without re-running.

## Failed approaches

- Tried: **Hard absolute floor of 0.5 on rerank score** (original design) — Failed because: it was calibrated on formal phrasing where gold scores 0.83–0.99, but real casual/abbreviated traffic scores far lower (gold at 0.439, even 0.00071), so the floor cut valid gold → empty context → hallucination. Avoid when: tempted to pick "a reasonable-looking threshold" from formal-phrasing samples. **Cross-cutting** (score-comparability) — pointer promoted to index.md.
- Tried: **Unconditional top-1 keep + absolute floor as a scope gate** (`top_score < FLOOR → []`, the intermediate design) — Failed because: id=4 proved a valid query can have gold top-1 at 0.00071; the gate refuses it. An absolute number cannot separate "out of scope" from "in scope but phrased vaguely" — both push the whole score column toward zero. Avoid when: tempted to make the reranker score double as an out-of-scope detector.
- Tried: **Absolute floor as a rank≥2 sanity sieve alongside the ratio** — Failed because: the floor-sweep showed it removes no noise the ratio hasn't already removed, while costing gold. Avoid when: assuming "a tiny floor can't hurt" — the data says it only hurts here.
- Tried: **Scoring reranker against the rewritten subqueries instead of the original question** (considered, not shipped) — Failed because: it makes scores non-comparable across a query's own subqueries (each subquery is its own scale), which breaks any threshold/ratio applied to the merged pool, and it launders bad rewrites (a drifted subquery's high-scoring junk gets legitimized with no original-question referee). Avoid when: trying to fix multi-hop where gold covers only part of the composite question — fix that with a wider ratio (keep rank-2), not by changing the scoring query.

## Nuances agreed with the user

- **Ratio keeping all near-tied articles is a feature, not a bug.** For same-concept-across-levels articles the reranker cannot tell bậc apart, so forcing a single winner is wrong ~half the time (id=13 picks Đ24 over gold Đ15). Keeping both and pushing the choice down to the answer LLM is the intended trade: extra context is recoverable (LLM filters), missing context is fatal.
- **"Empty context" now means only "retrieval pool empty."** Dropping the floor narrows the entrance to Plan C's deterministic refusal to the zero-candidate case — which hybrid retrieval almost never produces. Out-of-scope rejection ("giá vàng hôm nay") is therefore **not** handled by the reranker layer anymore; it is deferred to the router / answer-prompt. This is accepted debt, named deliberately.
- **Two abbreviated questions (id=11, id=22) are permanently unreachable by ratio** — their gold sits at rank 6 / ratio 0.11, or the whole score column collapses (id=11 like id=4). These are recall / wrong-level problems, not thresholding problems. Seeing them stay red in a future e2e run is expected, not a regression of this change.
- **graph-RAG for cross-reference is overkill** — the problem is "same concept exists in parallel across 3 degree levels (ĐH/KS/ThS)", not a chain of entity references. A `bậc`+`chương` metadata field at indexing time (soft-boost or chapter-union, once the user's degree level is known) is the proportionate tool. The user's "union Chương I ∪ query's chapter" idea presumes we already know the query's chapter/level — which is the actual hard part; that is why degree-selection-before-chain is the prerequisite. None of this is built yet.
